Blogs (Proyectos de Infraestructura y Bases de Datos)

Blog 1: Administración y Despliegue de Base de Datos Servidor con Ubuntu Server

a. Descripción

Configuración de un entorno de servidor virtualizado para gestionar bases de datos relacionales en alta disponibilidad y acceso remoto seguro.

b. Requerimientos del cliente

Se solicitó un entorno aislado en Linux accesible mediante OpenSSH que permita alojar un sistema gestor de bases de datos seguro y eficiente para almacenamiento de inventarios.

c. ¿Cómo se diseñó la solución?

Se optó por una máquina virtual en Oracle VM VirtualBox ejecutando Ubuntu Server. Se definió una arquitectura de red en modo adaptador puente (Bridge) para asignación de IP estática y reglas de firewall estrictas.

d. ¿Cómo se implementó la solución?

Se instaló la imagen de Ubuntu Server, se configuró el servicio SSH para conexiones remotas con claves criptográficas y se instaló el motor gestor de base de datos ejecutando scripts de inicialización y asignación de usuarios con privilegios restringidos.

e. ¿Cuál fue el resultado?

Un servidor funcional y robusto listo para producción escolar, con tiempos de respuesta óptimos y conectividad remota validada.

Blog 2: API RESTful en Python Flask con Almacenamiento en SQLite y JSON

a. Descripción

Desarrollo de un servicio web tipo API REST para la gestión y control de inventarios con persistencia de datos relacional y respaldo en archivos JSON.

b. Requerimientos del cliente

Permitir operaciones CRUD (Crear, Leer, Actualizar, Eliminar) de productos a través de endpoints HTTP accesibles para aplicaciones web o móviles.

c. ¿Cómo se diseñó la solución?

Se estructuró una arquitectura de backend ligera con Python utilizando el microframework Flask, definiendo modelos de datos relacionales en SQLite y serializadores JSON para las respuestas de la API.

d. ¿Cómo se implementó la solución?

Se construyeron las rutas HTTP (`GET`, `POST`, `PUT`, `DELETE`), integrando manejo de excepciones, validación de parámetros de entrada y almacenamiento persistente en la base de datos local.

e. ¿Cuál fue el resultado?

Una API REST rápida y funcional que responde en formato JSON con soporte para pruebas mediante Postman y consumo desde aplicaciones cliente.
